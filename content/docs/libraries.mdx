## Library ID

| 来源 | 形态 |
| --- | --- |
| Git 仓库 | `/owner/repository` |
| Website | `/websites/slug` |
| 上传文档 | `/docs/slug` |
| Notion | `/notion/slug` |
| 分级 Library | `/websites/slug/sub-slug`（`docs`、`notion` 同理，最多四级） |
| 指定版本 | `/owner/repository/version` |

Slug 变更保留 Redirect，API 返回新的 Library ID。

`websites`、`docs`、`notion` 下的 slug 可以分级：`/websites/ethereum/whitepaper` 是独立的 Library，目录中归在 `/websites/ethereum` 之下。一个 ID 先按最长存在的 Library ID 解析，剩余的一段才视为版本，所以 `/websites/ethereum/<版本标签>` 仍然固定 `/websites/ethereum` 的那个版本。访问规则里 `/websites/ethereum/*` 覆盖该库及其下全部分级库。

## 版本不可变

每个 Version 冻结 Source Digest、解析器版本、Chunker 版本和 Embedding 模型。发布通过原子切换 `current_version_id` 完成。

查询在请求开始时固定 Version，因此**刷新期间不会混合新旧 Chunk**；刷新失败时旧版本继续可用。
