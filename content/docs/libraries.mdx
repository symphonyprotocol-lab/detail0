## Library ID

| 来源 | 形态 |
| --- | --- |
| Git 仓库 | `/owner/repository` |
| Website | `/websites/slug` |
| 上传文档 | `/docs/slug` |
| Notion | `/notion/slug` |
| 分级 Library | `/websites/slug/sub-slug`（`docs`、`notion` 同理，最多四级） |
| 指定版本 | `/owner/repository/version` |

Slug 变更保留 Redirect，API 返回新的 Library ID。

`websites`、`docs`、`notion` 下的 slug 可以分级：`/websites/ethereum/whitepaper` 是独立的 Library，目录中归在 `/websites/ethereum` 之下。一个 ID 先按最长存在的 Library ID 解析，剩余的一段才视为版本，所以 `/websites/ethereum/<版本标签>` 仍然固定 `/websites/ethereum` 的那个版本。访问规则里 `/websites/ethereum/*` 覆盖该库及其下全部分级库。

## 版本不可变

每个 Version 冻结 Source Digest、解析器版本、Chunker 版本和 Embedding 模型。发布通过原子切换 `current_version_id` 完成。

查询在请求开始时固定 Version，因此**刷新期间不会混合新旧 Chunk**；刷新失败时旧版本继续可用。

## 构建计费

自建知识库的每次构建（首次索引和之后的刷新）按新增内容量折算成 API Call，从当期套餐额度扣减，额度用尽后扣调用包余额：

```text
构建费 = 基础费 + ⌈新增 Token ÷ 每 Call Token 数⌉ + ⌈抓取页数 ÷ 每 Call 页数⌉
```

当前费率为每次构建 1 Call 基础费、每 20,000 新增 Token 计 1 Call、每抓取 5 页计 1 Call。抓取页数只对 Website、llms.txt 和 OpenAPI 来源计；Git 仓库、Notion 和上传文档不计。

| 情况 | 费用 |
| --- | --- |
| 来源未变化的刷新 | 不产生版本，不计费 |
| 构建失败 | 不计费 |
| 只有部分来源变化 | 只对变化的来源计新增 Token |
| 平台升级解析器、切块器或 Embedding 模型触发的重建 | 不计费 |
| 版本存证 | 不计费 |

费用只在版本发布成功时扣减。创建向导和「重新构建」按钮会先显示本套餐单次构建的费用上限；可用额度不足以支付基础费时会直接拒绝，而不是排队一个注定失败的构建。构建过程中若发现实际费用超出余额，会在 Embedding 之前停止，同样不计费。

单库容量是上限而不是额度：一个 20 MB 的满容量库约需 250 Call，Free 套餐一个月内建满 5 个这样的库会超出月度额度。每个版本消耗的 Call 显示在知识库详情页的版本历史里，Dashboard 也会把本期的检索调用和构建消耗分开列出。
